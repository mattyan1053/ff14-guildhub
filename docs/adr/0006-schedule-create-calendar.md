# 0006: スケジュール作成の候補日を週ページングのトグルボタンにする

> `/schedule create` の候補日入力を、今日起点の7日窓を週ごとにページングするトグルボタン(初期未選択のオプトイン)にする。選択済み候補日はEmbedのフィールドに正規形(YYYY-MM-DD)で保持し、時刻・タイトル・作成フロー等は ADR 0005 を引き継ぐ。ADR 0005 を supersede する。

## Context

ADR 0005 で `/schedule create` を対話ビルダーにし、候補日はセレクトメニュー(開始日/終了日+除外)で選ぶ設計にした。実機で使うと、日付をプルダウンで選ぶ操作が明確に使いづらい(ドロップダウンを開いて目的の日までスクロールして選ぶ手数)。

Discordにはネイティブの日付ピッカーが無く、さらに**週=7列のカレンダー格子は原理的に作れない**(ボタンは1行最大5個・1メッセージ最大5行=25個なので、7列を並べられない)。画像でカレンダーを描くことはできるが画像はクリックできず選択に使えない。

プルダウンの手数を減らす現実的な手段は、日付を**タップできるボタン**にすること。ただし週をめくるとその週のボタンは画面から消えるため、ADR 0005 の「途中状態はパネルのコンポーネント値(default選択)だけを真実源にする」では、表示外の週の選択を保持できない。状態モデルという 0005 の看板決定を変える必要があるため、0005 を supersede する新しいADRとして記録する。

## Decision

### 候補日 = 週ページングのトグルボタン
- 1ページ = **今日(JST)起点の7日窓**(offset*7 〜 offset*7+6 日)。offset は 0(今週)〜約8週先まで。**過去週は出さない**(前週ボタンは今週で止まる)。
  - 週=7ボタンは2行に分かれる(1行5個制約)。曜日はボタンのラベル(例 `7/22(水)`)で示す。列を曜日に揃えることはできない(格子は不可能)ため、実質「ページング式の7日ボタン窓」である。
- 各週の日は**初期未選択(オプトイン)**。タップで候補ON/OFFし、ボタンのスタイルで選択状態を示す。全週をプリフィル(opt-out)にすると、先を見ようとめくっただけで意図せず候補が増える事故が起きるため採らない。
- 前週◀/次週▶で窓を移動する。今週で◀、上限週で▶を無効化する。
- オプトインの手数を減らすため、表示中の週を一括でON/OFFする「**この週をまとめて選択/解除**」ボタンを添える。

### 状態はメッセージ(コンポーネント + Embed)が真実源
- **選択済みの候補日は Embed のフィールドに正規形(`YYYY-MM-DD`)のリストで保持**し、毎操作で読み戻す。表示中の週はページングボタンの customId に載せた offset で決まる。これによりサーバー側に途中状態を持たず(再起動耐性を維持・ADR 0004/0005 の「DBが真実源」を保つ)、週をめくっても選択が失われない。
- **時刻は ADR 0005 どおりセレクトメニュー**(複数選択、default マーク=コンポーネントを真実源)。時刻はページングしないためコンポーネント値だけで完結する。
- 結果として、**候補日は Embed フィールド / 時刻はコンポーネント default** と真実源が分かれる。イベントの説明文は Embed の description(タイトル/説明モーダル由来)に置き、候補日フィールドとは別なので競合しない。

### 0005 から引き継ぐ決定
- 作成はモーダルではなく**エフェメラルの対話ビルダー**。作成は ManageEvents で権限ゲート。
- 時刻プリセット(夜帯・30分刻み)+ 時刻のカスタム追加(モーダル)。タイトル/説明ボタン→モーダル。作成/キャンセルボタン。
- 基準タイムゾーンは **JST固定**。プリセット・7日窓の生成は application/domain 層に置き、discord 層は描画のみ(ADR 0003)。
- セッションは interaction トークンの ~15分制限内で割り切る。

### 0005 から落とす決定
- **候補日のカスタム自由入力(任意ラベルの日)を廃止**する。候補日はカレンダー由来の `YYYY-MM-DD` のみとし、Embed に保持する状態を均質・再構築可能に保つ。8週窓の外や飛び石の任意日は当面非対応(必要になれば後付けする)。
- 候補日の「開始日/終了日+除外」セレクトを廃止する(本ADRのトグルボタンに置換)。

## Consequences

- 候補日をプルダウンを開かずタップで選べる。週めくりで先の週も選べ、8週先までカバーする。
- 選択状態が Embed フィールドに可視化される(0005 が不採用とした「Embedテキスト保持」を採用)。フィールドは表示と状態の二役を担う。ユーザーに選択中の候補日が一覧で見えるフィードバックにもなる。
- 真実源が候補日(Embedフィールド)と時刻(コンポーネントdefault)で分かれ、復元経路が2種になる。往復テストもそれぞれ必要で、0005 の単一モデルより複雑になる。
- カレンダーの列は曜日に揃えられない(格子は不可能)。各ボタンに曜日ラベルを載せて補う。見た目は「週めくりの7日ボタン」であって月間カレンダーではない。
- 過去週は出さないため、過去日を候補にはできない。
- 候補日の任意入力を落とすため、8週窓外・飛び石の任意日は作れない(記録用途・遠い単発は別途検討)。
- ボタン主体になり、1メッセージ5行の制約内で候補日(2行)+ページング+時刻セレクト+操作ボタンを収める。行数の余裕は小さい。

## Alternatives

- **ADR 0005 のセレクト方式を継続**: プルダウンを開いて選ぶ手数が残り、本課題(やりづらさ)を解消できないため supersede する。
- **全週プリフィル(opt-out)+ページング**: めくった週が自動で全候補入りし、意図しない候補増加が起きるため不採用。オプトインにする。
- **真のカレンダー格子(月間・曜日整列)**: 1行5ボタン制約で7列を並べられず不可能。画像描画はクリックできず選択に使えないため不採用。
- **選択状態をサーバー(インメモリMap / DBのdraft)で保持**: 再起動で消える、または 0004/0005 の「DBが真実源・未完成draftを持たない」方針と衝突するため不採用。Embedフィールド保持にする。
- **週を月曜〜日曜に整列**: 今週に過去日が混ざり、そもそも列整列も5ボタン制約で崩れる。今日起点の7日窓にする。
- **候補日のカスタム自由入力を残す**: Embedに保持する状態に `YYYY-MM-DD` 以外の任意ラベルが混ざり、再構築が複雑になるため今回は落とす。
