# 0007: スケジュール作成フロー(期間指定+除外のカレンダー、時刻・タイトルの入力)

> `/schedule create` を、入力順(タイトル→説明→候補日→候補時刻)に沿った1枚のエフェメラルパネルにする。候補日は週ページングのカレンダーで「期間を範囲タップ→個別タップで除外」。候補時刻は既定 ○/△/✖ で任意にモーダル追加。タイトル/説明はパネル内ボタン→モーダル(コマンド引数は使わない)。すべて Embed に即プレビュー。ADR 0006 を supersede する。

## Context

`/schedule create` の作成体験を、実機フィードバックで繰り返し見直した結果、最終的な作成フローが固まった。運用者の頭の中の入力順は概ね **タイトル → 説明 → 全体の期間 → 細かな除外日 → 選択肢の種類** であり、これに沿った操作にしたい。

Discord の制約(繰り返し確認した事実):
- **日付/時刻ピッカーが無い**。週=7列のカレンダー格子も1行5ボタン制約で作れない。
- **モーダルはプレビューできない**(入力欄専用、送信するまで結果が見えない)。したがって「モーダルで手順を進めるウィザード+プレビュー」は不可能。
- 「プレビューしながら設定」を実現できるのは、**エフェメラルのメッセージ(Embed+ボタン)を1枚出し、操作ごとに即更新する**方式だけ。

ADR 0006 は候補日を「初期未選択のオプトイン(1日ずつタップ)」にしたが、実運用では「まず全体の期間を決め、要らない日を外す」方が自然で手数も少ない。データモデル(ADR 0004 の回答語彙)は変えないが、候補日の操作モデルと作成フロー全体を更新するため、0006 を supersede する。

## Decision

`/schedule create`(**コマンド引数なし**)で、エフェメラルの1枚パネル(ビルダー)を出す。作成は ManageEvents で権限ゲート(ADR 0004)。パネルは入力順に沿って上から並べ、各項目を Embed に即プレビューする(Discord は本物のウィザードを作れないため1画面で代替)。

### タイトル / 説明
「タイトル/説明を編集」ボタン → モーダル(現在値プリフィル)。結果は Embed の title/description にプレビュー。**コマンド引数は使わない**(毎回打つのが面倒)。テキスト入力は Discord ではモーダルが唯一の手段のため、モーダルは「入力の瞬間」だけに使い、表示はパネルに統合する。

### 候補日:週ページングのカレンダー(期間指定 + 除外)
- 今日起点の7日窓をタップ式ボタンで表示。◀前週/次週▶で今週〜約8週先(過去週は出さない)。JST固定。
- **期間を範囲タップ**:「期間を指定」ボタン → 開始日タップ → 終了日タップで、その範囲の全日を候補にする(週をまたいでよい)。範囲指定の途中状態(開始待ち / 終了待ち+開始日)も Embed に保持する。
- **個別調整**:日ボタンのタップで1日ずつ追加/除外する。
- 選択済み候補日は Embed に **ANSI の月間カレンダー**(等幅・選択日を背景色ハイライト)で表示する。これが状態の真実源(パネル自身が真実源、サーバー状態を持たない・再起動耐性を維持)。複数月対応。

### 候補時刻:既定 ○/△/✖、任意でモーダル追加
- 既定は回答が ○いつでも / △未定 / ✖不可 のみ(ADR 0004 の時刻スロット0個)。
- 「時刻を設定」ボタン → 複数行モーダル(現在の時刻をプリフィル)で追加/削除 → 送信で置き換え。結果は Embed にプレビュー。プルダウンやプリセットは使わない。

### 回答語彙・データモデル
ADR 0004 のまま。回答は ○いつでも / 主催定義の時刻 / △未定 / ✖不可 の4種で決定的。**任意ラベルのカスタム選択肢タイプは持たない**(集計とデータモデルを単純に保つ)。

### レイヤー境界
週窓生成・JST整形・カレンダー描画は discord.js 非依存のロジックとして domain/render 層に置き、interaction ハンドラは薄く保つ(ADR 0003)。

## Consequences

- 入力順に沿った1枚パネルで、タイトル→説明→期間→除外→時刻を、すべてプレビューしながら設定できる。
- 「期間を範囲タップ→個別に除外」で、連続した期間を数タップで候補化できる(オプトインで1日ずつ入れるより速い)。飛び石は個別タップで足す。
- 範囲タップのモード(開始待ち/終了待ち)という途中状態を Embed に持たせる分、render/parse の分岐が増える。ただしサーバー状態は持たず、パネル自身が真実源という原則は保つ。
- 候補日と時刻・タイトルはすべて Embed 由来で復元する(パネル真実源)。時刻の StringSelect は廃止した。
- カレンダーは曜日列に揃えられない(格子は不可能)。各セルに日番号、選択日を色で示す。**ANSI 色は PC/スマホアプリで表示され、一部クライアントでは素テキストになる**(日付は読める)。
- 過去週・8週より先・任意ラベルの選択肢は当面対象外(必要になれば後付け)。
- 作成体験を1つのフローに確定させた。以降の細かな調整はコードとテストで表現し、決定自体が覆ったときだけ新しい ADR で置き換える。

## Alternatives

- **候補日を初期未選択のオプトインのみ(ADR 0006)**: 連続期間で1日ずつタップするのが手数多め。期間の範囲タップを足す。
- **期間を開始/終了の2プルダウンで指定**: 選択肢が最大25日ぶんに制限され8週窓に届かず、プルダウン操作も重い。カレンダーの範囲タップにする。
- **期間をモーダルで日付入力**: 年の推定など日付解釈に曖昧さが残り、入力の手間も出る。タップで完結させる。
- **タイトル/説明をコマンド引数にする**: 毎回打つのが面倒。パネル内の編集ボタン(モーダル)にする。
- **タイトル/説明・手順をモーダルのウィザードにする**: モーダルはプレビューできず、カレンダー表示も出せない。メッセージ1枚のパネルにする。
- **任意ラベルのカスタム選択肢タイプを持つ**: 回答語彙が可変になり集計・データモデル(ADR 0004)が複雑化。○/時刻/△/✖ の決定的語彙を維持する。
