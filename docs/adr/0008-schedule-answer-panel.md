# 0008: スケジュール回答UI(例外マーキング型・完了でコミット)

> `/schedule` の回答を、自分の回答をカレンダーでプレビューするエフェメラルの下書きパネルにする。デフォルトは参加可(**未入力=いつでも**)とし、不可/未定/時刻の例外だけを「週送りの日ボタンで対象日を選ぶ → 適用selectで種別を選ぶ」でマークする。パネル自身を下書きの真実源とし(ADR 0007 と同型)、「完了」で全候補を一括 upsert(例外はその種別・残りは yes)して初めて DB 保存・公開メッセージ更新する。回答語彙・データモデルは ADR 0004 のまま。

## Context

回答体験を実機で見直したところ、現行の回答パネル(候補1日=プルダウン1つを4件ずつページング/選ぶと即保存)には次の問題があった。

- **一覧性がない**。作成・表示にはカレンダーがあるのに、回答側だけプルダウンの列で、自分がどの日をどう答えたか俯瞰できない。
- **1日1操作**。候補が最大 93 日(ADR 0004 / limits)だとページ数が多く、「今週は水曜以外OK」を入れるのに何度もめくって選ぶ。
- **全日を等価に選ばせる**。FF14 固定活動は「参加可がデフォルト、不可/未定/時刻だけが例外」(ADR 0004 の活動判定=誰も不可でなければ活動あり、回答ゼロでも活動あり)なのに、UI はそれを表現していない。

Discord の制約(ADR 0007 で確認済みの事実)は回答側でも同じ:日付/時刻ピッカーは無い、モーダルは入力欄専用でプレビュー・セレクトを持てない、プレビューしながらの設定はエフェメラルのメッセージ1枚を操作ごとに即更新する方式でしか作れない。

データ語彙・集計(ADR 0004)は変えない。変えるのは**回答の入力体験**であり、ADR 0007 が作成体験を1枚パネルにしたのと対になる。

## Decision

`/schedule` の公開メッセージの「回答する」ボタンで、エフェメラルの**下書きパネル**を出す。パネルは自分専用で、操作ごとに即更新する。

### 既定は参加可(未入力=いつでも)

- 個人の1日の回答は **参加可(いつでも) / 主催定義の時刻 / 未定 / 不可** の4種(ADR 0004 の語彙)。
- **未入力 = いつでも参加可**として扱う。全日 OK の人はどの日もマークしなくてよい。ユーザーは**例外(不可・未定・時刻指定)だけ**をマークする。

### カレンダープレビュー(自分の回答)

- Embed に、作成・表示と同じ等幅 ANSI の月間カレンダーを出し、**自分の下書き回答**で各候補日を塗り分ける(参加可=緑系 / 時刻=時刻色 / 未定=黄 / 不可=黒)。色と意味の対応は凡例で固定する。色は表示と共通(同じ時刻→同じ色)。
- 「未入力/参加可は『いつでも参加可』として扱う」旨を明記する。

### マーク操作(週の日ボタンで対象日を選ぶ → 適用selectで種別を選ぶ)

- **週送り + 日ボタン**:作成ビルダー(ADR 0007)と同様に、候補日を含む週を ◀ 前週 / 次週 ▶ で移動し、その週の候補日を**日ボタンとして並べる**(JST固定・候補日のみ・最大7)。プルダウンを開かなくても「その週に回答できる日」がボタンで見えている。ボタンのタップで対象日を**トグル選択**(選択中は色付きボタン)、下書き種別はボタンのラベル記号(◯参加可/✕不可/△未定/🕒時刻)で示す。週内なら複数日をまとめて選べる。
- **適用 single-select**:選んだ日にまとめて種別を適用する。選択肢は `◯ 参加可に戻す(例外を取消) / <各時刻> / △ 未定 / ✕ 不可`。**「いつでも」は正の回答としては選択肢に出さない**(未入力=いつでものため冗長)。代わりに「参加可に戻す」を、いつでもを答える手段ではなく**例外を取り消す操作**として1つ置く。
- **ページ単位は週で固定**:日付select に全候補を載せて25件ごとに割る方式は、区切りが不均衡で「今どの範囲を選べるか」がプルダウンを開くまで分からず扱いづらい。週=均一な単位にし、選べる日をボタンで見せる。1週=最大7日なので select 上限(25)にも当たらない。

### 下書きの真実源はパネル自身(サーバー状態を持たない)

- マーク中は DB に書かず、**パネルのメッセージ(下書き明細フィールド + 週の位置 + 選択中の日ボタン)を下書きの真実源**にする(ADR 0007 の作成ビルダーと同じ原則、再起動耐性を維持)。パネルを開いたときは、その人の既存回答を下書きの初期値として反映する。選択中の日は日ボタンの色(Primary)で持つ。
- 下書きの真実源は、Embed の**「下書き明細」テキストフィールド**(例外を種別ごとに `YYYY-MM-DD` の一覧で持つ人間可読な表記)とする。**背景色からの逆引きは採らない**:Discord の ANSI 背景色は実質4色程度しか判別できず、時刻スロットは最大22種まで作れる(limits)ため、色だけでは「どの時刻か」を一意に復元できない。カレンダーは下書き明細から描画する**表示専用**とし、色が重複しても真実源には影響しない。

### 「完了」で一括コミット

- 「完了」ボタンで、**イベントの全候補について一括 upsert** する:マークした日はその種別(時刻/未定/不可)、マークの無い残りの日は **yes(いつでも)**。これで初めて DB 保存し、公開メッセージを1回だけ更新する。押した本人は「回答済み」に入る(全日 OK で何もマークしなくても、完了を押せば yes が全候補に入り回答済みになる)。
- 「参加可に戻す」でマークを外した日は、完了時に yes として upsert される。よって**回答の削除機能は不要**(常にいずれかの種別を upsert する)。

### 回答語彙・データモデル

ADR 0004 のまま。`yes`(いつでも)は選択肢として**パネルには出さない**が、完了時の残り埋めに内部的に使うため**データモデルには残す**。回答は upsert で表現し、行削除は導入しない。

### アプリケーション層 / 境界

- 一括コミットのため、application 層に **`addResponses`(1ユーザーの複数候補への回答を一括 upsert し、集計を1回返す)** を追加する。既存 `addResponse`(単発)とは別。
- カレンダー描画・下書きのパース/復元は discord.js 非依存のロジックとして render 層に置き、interaction ハンドラは薄く保つ(ADR 0003)。

## Consequences

- 自分の回答をカレンダーで俯瞰しながら、例外だけを「複数日選択→適用」で一括入力できる。「月〜金を選んで不可」が数タップで済む。
- 未入力=いつでもにより、全日 OK の人は例外を触らず完了を押すだけでよい。UI が「デフォルト参加可・例外だけ」を素直に表現する。
- **「完了」を押すまで何も保存されない**。マーク途中で離脱(モバイルでのエフェメラル消失など)すると下書きは失われる。即保存をやめた副作用であり、これを受け入れる(完了=確定を明示する体験と引き換え)。
- **「回答済み」の意味が「完了を押した人」になる**。例外を入れず完了を押した人も yes が全候補に入るので回答済みに数えられる。逆に完了を押さない限り集計に反映されない。公開メッセージの「回答済み N/8」「8人揃えば確定」の目安はこの定義で読む。
- 下書きの真実源は「下書き明細」テキストフィールドから復元する。パース失敗時は空の下書き(全日=未入力=参加可)にフォールバックする。ANSI 背景色に依存しないので、時刻スロットが色数を超えても真実源は壊れない(カレンダーの色は表示上重複しうるが、意味は明細と凡例が担う)。
- 旧 UI で付いた既存回答(yes/time/maybe/no)はそのまま残る。新パネルは開いたときに下書きへ反映し、完了を押すまで変えない。データ語彙・集計(ADR 0004)は不変なので互換は保たれる。
- その週の候補日が日ボタンで見えており、複数日をタップして種別を一括適用できる(週内で「複数日まとめて回答」)。週をまたぐ一括選択はできない(週ごとに送って適用する)が、区切りが均一で「今選べる範囲」が一目で分かる。プレビューのカレンダー Embed は全月を表示する。
- 日ボタン(最大7)+週ナビ+適用select+完了/閉じるで、Discord の行数上限(5行)にちょうど収まる。候補日が0の週は無いので空行にならない。
- 回答入力体験を1つのフローに確定させた。以降の細かな調整はコードとテストで表現し、決定自体が覆ったときだけ新しい ADR で置き換える。

## Alternatives

- **候補1日=プルダウン1つのページング(現行)を維持**:一覧性がなく1日1操作で手数が多い。カレンダー+複数日一括に置き換える。
- **適用UIを「不可/未定/参加可」ボタン + 時刻 select に分ける**:よく使う操作は1タップで速いが、行数を1つ多く使い、適用が2行に分かれて一体感が落ちる。単一 select に統一して簡潔にする(実装も素直)。
- **マークごとに即 DB 保存(現行の即保存を踏襲)**:半端な回答が公開側にちらつく。マーク解除の即時戻しに削除や再 upsert が要る。完了で一括コミットにして、確定の瞬間を明示する。
- **「いつでも」を正の回答として選択肢に残す**:未入力=いつでもと冗長で、回答済みの定義も二重になる。正の回答からは外し、完了時の残り埋めに内部利用するだけにする。
- **回答の削除機能(deleteResponse)を追加して「参加可=行を消す」で表現**:repository とデータ操作に削除経路が増える。完了時に常に yes を upsert する方式なら削除は不要で、upsert だけで完結する。
- **日付を1つの select にまとめ、25件ごとにページ送りする**:週をまたいだ一括選択はできるが、区切りが不均衡で「今どの範囲を選べるか」がプルダウンを開くまで分からず扱いづらい。週=均一な単位にし、選べる日をボタンで見せる方式にした。
- **日付選択を月単位の select にする**:1ヶ月の候補日が25を超えると select 上限に当たり、月境界で区切りもぶれる。週の日ボタンにして回避する。
- **日ボタンではなく週の日付 multi-select にする**:選べる日がプルダウンを開くまで見えない。ボタンで常時見せる。
- **回答をモーダルのウィザードにする**:モーダルはプレビューもセレクトも持てず、カレンダー表示ができない。エフェメラルのメッセージ1枚のパネルにする。
